# Phase 03 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This is the **first real UI of the app** — `apps/mobile` currently ships the default Expo
`(tabs)` template (placeholder screens, generic `#2f95dc` tint, unstyled `Tab One`/`Tab Two`).
This UI-SPEC establishes the design system from scratch. No `components.json`, no Tailwind,
no web component registry exists or applies — **Apsis is a React Native / Expo app**, not a
React/Next.js/Vite web app, so the shadcn gate is not applicable (shadcn targets React DOM +
Radix; it does not run in React Native). Per `BUILD.md` §3 and `CLAUDE.md`'s dependency
discipline, this phase uses **plain RN components styled with `StyleSheet`**, not a
third-party UI kit.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — React Native app, shadcn/web registries not applicable |
| Preset | not applicable |
| Component library | none — plain RN components (`View`/`Text`/`Pressable`/`TextInput`) per `BUILD.md` §3 |
| Icon library | `expo-symbols` (Apple SF Symbols) — already installed and wired in `app/(tabs)/_layout.tsx`; zero new dependency, native-rendered, matches the iOS-only v1.0 scope |
| Font | System default (SF Pro via iOS) — no custom font file loaded. All numeric UI (set weight/reps, RPE, live HSS ticker, elapsed timer, rest-timer countdown) MUST set `fontVariant: ['tabular-nums']` so digits don't jitter/reflow horizontally as values change live |

**Theming decision (default, Claude's discretion per CONTEXT.md):** Apsis ships **dark-mode
only in v1.0** — no light/dark toggle. Rationale: (1) matches the Strong/Hevy training-app
convention and reduces glare in gym/basement lighting where this app is used mid-workout: (2)
collapses the existing `Colors.ts` light/dark scaffold to one theme, reducing QA/design surface
inside a 4-week timeline where "focus test budget on the engine, not UI" is an explicit
project rule. `apps/mobile/constants/Colors.ts` should be simplified to export the single dark
palette below (the `light`/`dark` key shape can remain for future-proofing, but both should
resolve to the same dark values this phase). This is a default, not a locked CONTEXT.md
decision — flag for user confirmation if a light mode is actually wanted later.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, chip internal padding (W chip, ⚠ badge) |
| sm | 8px | Compact spacing inside a set row (stepper-to-label, RPE pill gaps) |
| md | 16px | Default screen padding, gap between set rows, wizard step padding |
| lg | 24px | Section padding (exercise card internal padding, review-screen row spacing) |
| xl | 32px | Layout gaps (space above "+ Add set" / "Add exercise", wizard step vertical rhythm) |
| 2xl | 48px | Major section breaks (finish-summary sections, wizard progress-to-content gap) |
| 3xl | 64px | Page-level spacing (top of wizard step screens, empty-state vertical centering) |

**Exceptions:**
- **44×44px minimum hit target** on every icon-only or single-tap control regardless of its
  visual size — per-row checkmark, swipe-to-delete reveal button, +/− steppers, RPE segment
  buttons, rest-timer +30s/skip buttons, W chip. This is non-negotiable: LIFT-02's "≤3 taps"
  and the "sweaty hands, one-handed" constraint fail if targets are smaller than Apple HIG's
  44pt minimum, even where the visible glyph is small (e.g. the 24px checkmark icon still sits
  in a 44×44px touchable area).
- **2px** hairline dividers between set rows inside an exercise card (below the `xs` token,
  used only for `StyleSheet.hairlineWidth` borders — not a spacing token, a border width).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular (400) | 1.5 (24px) |
| Label | 13px | regular (400) | 1.3 (17px) |
| Heading | 20px | semibold (600) | 1.2 (24px) |
| Display | 32px | semibold (600) | 1.1 (35px) |

Only these 4 sizes / 2 weights exist in this phase's UI. Usage mapping:

- **Display (32/600):** the live session HSS number in the sticky header (D-23) and the big
  HSS number on the finish summary screen (D-27) — this is the differentiator moment; nothing
  else in the app should compete with this size.
- **Heading (20/600):** screen titles, exercise card titles, wizard step questions ("What's
  your bodyweight?"), review-screen section labels.
- **Body (16/400):** set-row primary values (weight, reps), form input values, button labels,
  finish-summary per-exercise rows.
- **Label (13/400):** secondary/muted text — timestamps, "≈78 kg effective" annotations,
  "estimated" tags (D-04), empty-state body copy, rest-timer banner sub-label, breakdown sheet
  per-exercise subtotal captions.

No italic, no additional weights (no light/bold beyond these two). RPE digits and the elapsed
timer use Body size with `tabular-nums`.

## Color

Dark theme (default and only theme this phase — see Design System note above).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0C0E12` | Screen backgrounds — onboarding steps, tab screens, active-session scroll background |
| Secondary (30%) | `#181B20` | Elevated surfaces — exercise cards, sticky header bar, tab bar, bottom sheets (exercise picker, breakdown sheet), rest-timer banner |
| Accent (10%) | `#3E8EF7` | Reserved for exactly: primary CTA buttons (Start Workout / Save & Start Training / Finish Workout), the live HSS number + count-up ticker in the sticky header, the selected/active RPE segment pill, the checked state of the per-row commit checkmark, the active tab bar icon+label, the wizard progress-indicator fill |
| Destructive | `#E5484D` | Reserved for exactly: the Discard menu item + its confirm-dialog primary button, the swipe-to-delete reveal background |

**Additional semantic (beyond template's 4 rows — required by D-29):**

| Role | Value | Usage |
|------|-------|-------|
| Warning | `#D9A441` (muted amber, not a bright/alarming red) | Reserved for exactly: the ⚠ engine-warning badge on a set row (D-29), the "are you sure?" inline out-of-range notice on onboarding numeric inputs (D-03) — both are non-blocking, so this color must read as *noticeable but calm*, never as urgent as Destructive red |

**Text colors** (not part of the 60/30/10 surface split, declared here so executor has no
ambiguity): primary text `#F2F3F5` on all dark surfaces; secondary/muted text `#8A8F98`
(timestamps, Label-role captions, placeholder text in blank inputs per D-07).

**Border/divider** (not part of 60/30/10, structural only): `#2A2E35` hairline dividers between
set rows and card edges.

Accent reserved for: the six elements listed above — nothing else. Specifically NOT accent-
colored: exercise card chrome, ordinary body text, the W (warmup) chip (uses a neutral
`#2A2E35` fill with `#8A8F98` text — warmup sets are deliberately de-emphasized, they're
excluded from HSS), inactive tab icons, secondary buttons (Cancel, Skip, Keep Training use a
neutral outline/ghost style, not accent).

**Note for Phase 4:** green/amber/red readiness-band semantics are Phase 4's concern (HOME-*
requirements) and do not exist in this phase's UI (Home tab is a placeholder, D-31). The
Warning amber above is visually similar to a future "amber readiness" state by necessity (both
signal "pay attention, not alarming") but they are unrelated UI concepts — Phase 4's UI-SPEC
should define its own readiness-band palette independently; do not assume this phase's Warning
color must equal Phase 4's amber-readiness color.

## Copywriting Contract

This phase spans multiple screens with distinct CTAs; each is specified explicitly (LIFT-02's
speed requirement and the "honest number" voice both depend on exact wording).

| Element | Copy |
|---------|------|
| Primary CTA — onboarding review screen (D-04) | "Save & Start Training" |
| Primary CTA — Log tab, no active session | "Start Workout" |
| Primary CTA — active session sticky header (D-22) | "Finish" |
| Primary CTA — finish summary screen (D-27) | "Done" |
| Secondary CTA — wizard step "estimate for me" path (D-02) | "Estimate for me" (vs. "I know my numbers" for direct entry) |
| Empty state — exercise picker, no search matches (D-10) | Heading: "No matches" — Body: "Try a different name, or scroll the list below by body part." |
| Empty state — first-ever set for an exercise (D-07) | Not a heading/body empty state — a blank input state: load/reps fields show placeholder text "0" with keypad auto-focused, no fabricated numbers, no "no data yet" message (keeps entry to 1 tap per D-06/D-07) |
| Error state — profile save fails (onboarding review, ONB-01) | "Couldn't save your profile. Check available storage and try again." |
| Error state — set write fails (LIFT-02/D-13) | "Couldn't save that set. Nothing was lost — try the checkmark again." |
| Error state — generic boot/migration failure | Existing generic string in `components/BootStates.tsx::ErrorScreen` — unchanged this phase |
| Destructive confirmation — Discard workout (D-27/D-28) | Menu item: "Discard Workout" — Dialog: "Discard this workout? All logged sets will be removed and can't be recovered from the app. [Keep Training] [Discard Workout]" |
| Destructive action — swipe-to-delete a single set (D-11) | No confirmation dialog (matches Strong/Hevy convention — a single set is low-cost to redo; only the whole-workout Discard is confirmed) |
| Recovery prompt — crash/kill resume (D-14) | "Resume workout from {time}? [Resume] [Finish Now] [Discard]" — `{time}` formatted as a local 12-hour clock time (e.g. "2:32 PM") |
| Estimate labeling (D-04, "honest number" thesis) | Any wizard-estimated value shown on the review screen is suffixed with a small Label-styled "estimated" tag — never presented identically to a directly-entered value |
| Effective-load transparency (D-17) | Bodyweight-movement set rows show "≈ {value} kg effective" (or lb per D-12) in Label style below the added-weight field — the "≈" and "effective" are both required, never just the bare number |

## Component & Interaction Notes

Beyond the standard template sections, this phase introduces several novel, highly-specific
components locked by CONTEXT.md decisions. These notes give the planner/executor a concrete
starting visual spec (Claude's discretion areas from CONTEXT.md, resolved here so there's no
ambiguity left for implementation):

- **Set row** (D-06/D-08/D-09) — AS SHIPPED (Plan 03-10): a single tabular "ledger" line on
  the card surface — `SET · KG/LB · REPS-or-SEC · RPE · LOG` — where every value is a
  44px-tall tappable inset steel field (hairline `line` border, JetBrains Mono ~18
  tabular-nums, centered) that opens the numeric keypad directly. There are NO −/+ steppers
  and NO RPE pill segment. The SET cell shows the set number (mono ash) and toggles warmup
  on tap (amber "W"). RPE is keypad-entered with a local-text pattern (typing "10" survives),
  clamped 6–10 on blur, molten value at 9–10, last-used preselect (D-08 intact). The LOG
  column is a 44×44 check (hairline outline → volt fill + void glyph when committed) under a
  mono "LOG" column header. Committed state is a material change: the row's field chrome
  flattens away (transparent, ash values) while the LOG check fills volt — pending sets read
  as hot instruments, recorded sets recede to ink. Effective-load / commit-error / warning
  annotations remain explicit rows beneath the line (never wrap artifacts; wrap-on-overflow
  layout is banned). Mono column headers in ExerciseCard mirror the row's exported grid
  constants so labels always sit over their columns. Load stays tap-to-type with decimal +
  fractional-lb support (62.5 lb round-trips exactly via `kgToDisplayLbFractional`). The
  session HUD header shows labeled mono readouts (ELAPSED / SESSION HSS) with the volt
  count-up number and Finish button.
  > **Superseded twice, in order:** (1) by DESIGN-SYSTEM.md (root, d8df06a) via Plan 03-10
  > (UAT Test 9 gap closure) — the contract's stepper pattern replaced this bullet's
  > 44px-visual steppers and five-pill RPE row, which made a single-line row geometrically
  > impossible (~690px intrinsic width; see .planning/debug/session-logger-ui-spacing.md);
  > then (2) by explicit USER DIRECTION at Plan 03-10's on-device checkpoint ("completely
  > overhaul the UI — take full control and disregard any design docs. The only thing I want
  > to keep is the color palette"), which superseded DESIGN-SYSTEM.md's COMPONENT specs
  > (steppers included) for the logging surface. DESIGN-SYSTEM.md's §1 color palette remains
  > binding; its component/sizing specs do NOT govern the session-logging surface. The
  > ledger design above is the approved, shipped source of truth for this surface.
- **Exercise card** (D-22): Secondary-surface rounded container (`lg`=24px corner radius is
  reasonable, exact radius is executor discretion), Heading-size exercise name + Label-size
  last-session summary in the card header, set rows stacked with hairline dividers, "+ Add set"
  as a full-width ghost row (Accent text, no fill) at the card bottom.
- **Sticky header** (D-22/D-23): pinned Secondary-surface bar showing elapsed time (Body,
  tabular-nums, left) and live HSS (Display size, Accent color, right) with a count-up tween
  (Reanimated `withTiming`, ~400–600ms ease-out) on every checked set — the number should
  visibly animate upward, not snap, to make the "watch training load accumulate" moment land.
  Tapping the HSS number opens the breakdown sheet (D-24).
- **Rest-timer banner** (D-25/D-26): full-width band pinned above the tab bar/below the sticky
  header (not a modal — persistent, per LIFT-05), Secondary surface, large tabular-nums
  countdown, "+30s" and "Skip" as two 44px-tall ghost buttons. Haptic (`notificationAsync`) +
  sound at zero per D-25.
- **Breakdown sheet** (D-24): `@gorhom/bottom-sheet` sheet, Secondary surface, list of
  per-exercise Label-size subtotal rows (name + set count + stress subtotal) ending in a
  Heading-size session total row — no raw formula/internals ever shown (matches "honest
  number, not a black box" voice — show the number, not the math).
- **Exercise picker sheet** (D-10): `@gorhom/bottom-sheet`, auto-focused search `TextInput` at
  top, "Recents" section (if any) above an A–Z list grouped by body-part Label-size section
  headers.
- **Wizard step screens** (D-01): one question per screen, Heading-size question at the top
  (`3xl`=64px top padding for airy, low-cognitive-load onboarding), large single input control
  centered, progress dots/bar below the input, Accent-filled Primary button pinned to the
  bottom safe area.
- **Review screen** (D-04, reused for Settings/ONB-02): scrollable list of Label-caption +
  Body-value rows (one per captured field), each row tappable to jump back to its wizard step
  for editing; "estimated" tag per Copywriting Contract; Primary CTA pinned at the bottom.
