<objective>
Close the one remaining Phase 03 UAT gap (Test 9, severity minor): the set-logging UI "is a little broken and spaced weird" because SetRow's intrinsic single-line width (~690px) is nearly double the ~329-361pt available inside an ExerciseCard on any iPhone, and `styles.row` wraps on overflow so every set row silently folds into 2-3 ragged lines instead of the UI-SPEC single ~56-64px row.

This is a layout-geometry fix, not a color/token fix (colors are already correct per Tests 7/9). Per the debug diagnosis (.planning/debug/session-logger-ui-spacing.md), the four flanking 44px steppers are the width hog that makes a single line impossible; the fix rebuilds SetRow as a genuine single-line row using compact tap-to-edit value fields (Strong/Hevy pattern) plus small RPE pills and checkmark whose 44pt touch targets come from hitSlop, aligns the card padding, and drops restyle-era width regressions.

Purpose: satisfy Success Criterion 3 ("log a set ... RPE via a persistent quick-row ... never behind a modal") with a clean, single-line row that matches 03-UI-SPEC.md lines 171-176.
Output: SetRow renders as one horizontal line with intentional annotation rows beneath it; edges align inside the card; on-device UAT Test 9 passes.
</objective>

  <action>
    Restructure SetRow so the primary controls live on ONE horizontal line and the existing annotation lines stack beneath it. The current `styles.row` mixes single-line controls and full-width (width:'100%') annotation children in one wrap container — that is exactly what folds the row. Split it:

    1. Outer container: a column View (flexDirection 'column'). It holds (a) an inner primary-row View and (b) the annotation lines (effective-load, commit-error, warning badge/message) as siblings BELOW the primary row. The effective-load / error / warning rows are intentional second lines per the phase constraints and MUST remain — they just move from being wrap artifacts to being explicit children of the outer column. Keep their existing conditional-render logic and copy strings verbatim (the effective-load "≈ … effective" string and the commit-error string are locked by the Copywriting Contract).

    2. Inner primary row: flexDirection 'row', alignItems 'center', a single line (do NOT set the wrap-on-overflow style — the property that currently forces folding must be absent). Order left-to-right: warmup "W" chip, load field, reps-or-duration field, RPE quick-row (6·7·8·9·10), commit checkmark. Use gap Spacing.xs (4) between these top-level items to conserve width.

    3. Density resolution (the core fix — per debug Suggested Fix Direction). The four 44px flanking −/+ steppers are why a single line is geometrically impossible (~690px content vs ~329pt available). Remove the flanking stepper Pressables from the load and reps/duration field groups. Each value field becomes a compact tap-to-edit control: the existing TextInput already opens the OS keypad on tap and already handles decimal load (the 62.5 fix) and blank/placeholder state — keep all of that input logic and the committed-set lock (editable={!locked}) unchanged, just drop the two `styles.stepper` Pressables that flank each field. This preserves Strong/Hevy entry speed (tap value → keypad → checkmark) while freeing ~110px. Keep the compact unit label ("kg"/"lb", "reps", or the pace mm:ss) beside each field. NOTE for Task 3 human-verify: this replaces the −/+ steppers with keypad entry; that trade is called out for on-device sign-off.

    4. Shrink the remaining small controls to VISUAL sizes below 44 and restore the 44pt touch target with hitSlop (multiples of 4, Apsis Design System v1): RPE pills → visual 28×28 (minWidth/height 28) with hitSlop 8; commit checkmark → visual 32×32 (borderRadius 16) with hitSlop 6; warmup chip stays at its current small size with its existing hitSlop. Do NOT use HIT_TARGET_MIN as the width/height of these controls anymore — that constant is the touch-target minimum, not the visual size. Keep every existing accessibilityRole/accessibilityLabel/accessibilityState and the disabled={locked} / disabled={committing} guards.

    5. Fix the restyle-era width regression on the value input: `styles.valueInput` currently sets fontSize 19 with a redundant fontWeight '600' on the single-face Archivo_800ExtraBold family. Reduce to a Body-scale size (16) and drop the fontWeight line (a weight that does not exist in a loaded single-face family can shift face selection/metrics on iOS). Keep fontFamily 'Archivo_800ExtraBold', keep tabularNums, keep textAlign 'center', and keep a minWidth just wide enough for the widest realistic value (load must fit "62.5"; a minWidth around 44 is fine).

    6. Keep the primary row's horizontal padding at Spacing.md (16) — Task 2 aligns the card header down to md so the left edges line up. Target primary-row height ~56-64px (via paddingVertical + control heights), matching UI-SPEC.

    Delete the now-unused `styles.stepper` / `styles.stepperLabel` rules (and the stepper step-helper wiring only if fully unused — the weight/duration/reps state setters that the TextInputs still call must stay). Do not leave the removed stepper style keys dangling. Do not add any new npm dependency.
  </action>
