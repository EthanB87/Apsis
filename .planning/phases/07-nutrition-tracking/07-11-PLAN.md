## Trust Boundaries

Attack surface is UNCHANGED by this gap-closure — the same OCR-recognized-text → food-row boundary
already established in 07-09. This plan only makes MORE of the (already bounds-checked, already
user-confirmed) recognized text reach the pre-fill; it introduces no new input source, no network,
and no new persistence path. Every value the new forward-scan finds still flows through the existing
`boundedNonNegative` gate and the mandatory editable confirm/edit form before any write.

| Boundary | Description |
|----------|-------------|
| OCR-recognized text → food pre-fill | Arbitrary recognized numbers are untrusted input (unchanged) |
