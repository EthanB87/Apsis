<objective>
Land the one Phase-1-schema ripple the engine requires (D-08): add a `config_version` column to
the `load_daily` table and generate the append-only drizzle migration that creates it. This lets
every computed daily-load row record which engine constant set produced it, enabling a post-launch
constant re-fit without ambiguity.

Purpose: The engine emits `CONFIG_VERSION` (plan 02-01); the db must have somewhere to store it.
This column + migration must exist now even though the write happens in Phase 3's
`recomputeLoadDaily()`. The phase CANNOT pass verification without the generated migration committed.
Output: Updated `schema.ts`, a generated `0001_*.sql` migration, and updated drizzle meta — all
append-only, wired into the existing bundled migration chain.

Artifacts this plan produces: `load_daily.config_version` column; the generated `0001_*.sql`
migration file + meta journal/snapshot entries.
</objective>
