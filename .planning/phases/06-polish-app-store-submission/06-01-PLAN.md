  <action>
    Create apps/mobile/scripts/check-icon-alpha.mjs: a Node ESM script that opens the PNG at
    apps/mobile/assets/images/icon.png, reads the IHDR chunk colorType (byte at offset 25 in a
    standard PNG), and exits 0 when colorType is 2 (RGB) or 0 (grayscale) and exits non-zero with a
    message when colorType is 4 or 6 (has alpha). Then flatten the existing icon onto solid
    background #0B0C0E (void — matches the app background and android-icon-background) and re-export
    as an opaque RGB PNG with zero alpha channel, keeping 1024x1024, 8-bit depth, and the existing
    plate-mark artwork exactly as-is. Use ImageMagick (`magick`) if available, else a one-off Node
    image tool (e.g. sharp via npx) — tool choice is discretion; the colorType-2 output is the gate.
    Do NOT redesign, recolor, or resize the mark — this is strictly the alpha-channel defect fix.
  </action>
  <verify>
    <automated>node apps/mobile/scripts/check-icon-alpha.mjs</automated>
  </verify>
  <done>icon.png is opaque RGB (colorType 2), 1024x1024, artwork unchanged; verifier script exits 0.</done>
  <acceptance_criteria>
    - `node apps/mobile/scripts/check-icon-alpha.mjs` exits 0.
    - The PNG IHDR colorType byte of icon.png is 2 (or 0), never 4 or 6.
    - Image dimensions remain 1024x1024, 8-bit depth.
    - Deliberately corrupting the check (pointing it at the pre-fix RGBA file) exits non-zero — the script actually gates, it is not a no-op.
  </acceptance_criteria>
