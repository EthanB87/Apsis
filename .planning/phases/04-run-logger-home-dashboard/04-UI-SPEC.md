# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is a **React Native / Expo app** (not React DOM) — the shadcn gate is not
applicable, consistent with Phase 03's UI-SPEC. This contract is a **hybrid** per CONTEXT.md
D-01: the home hero (200px HSS ring + readiness light) implements `DESIGN-SYSTEM.md`'s
signature component §5 largely as written; everything else (run entry form, session rows,
history rows) extends the **shipped Phase 3 ledger language** (`SetRow.tsx`,
`LiveHssHeader.tsx`, `HSSBreakdownSheet.tsx`, `finish.tsx`) which superseded
`DESIGN-SYSTEM.md`'s component-level specs for the logging surface at the Plan 03-10
checkpoint. The palette (`constants/Colors.ts`) is binding everywhere without exception.

All 29 CONTEXT.md decisions (D-01..D-29) are treated as locked inputs, not re-litigated here.
This document turns them into exact dimensions, colors, type sizes, and copy so the
planner/executor have zero open visual questions. A small number of genuine contract gaps
that CONTEXT.md left to "Claude's Discretion" (or didn't cover at all) are resolved explicitly
below and flagged as such.

## Spacing Scale

Reuses the live contract scale from `apps/mobile/constants/theme.ts` (`Spacing`) —
**do not introduce a second scale.**

| Token | Value | Usage this phase |
|-------|-------|-------------------|
| xs | 4px | Icon-to-label gaps, chip internal padding, gap between ring and status-light row |
| sm | 8px | Stat-tile internal gaps, readout label gaps, tooltip internal padding |
| md | 12px | Default control-to-control gap inside the run entry ledger card |
| lg | 16px | Default screen padding (Home/History/run-form horizontal padding), gap between stat tiles |
| xl | 24px | Section padding (space above the trend chart, space above "TODAY · N SESSIONS" header) |
| xxl | 32px | Layout gaps (space between the ring block and the stat-tile row) |
| xxxl | 48px | Major section breaks (space above the tab-bar-adjacent scroll end, finish-screen sections) |
| xxxxl | 64px | Page-level spacing (top padding above the ring on first paint, calibrating-state vertical centering) |

**Exceptions (fixed dimensions, not on the 4-base scale — these are components, not spacing):**
- **HSS ring diameters are fixed:** 200px (home hero) and 84px (finish mini-ring, per D-04).
  Never resize these ad hoc.
- **44×44px minimum hit target** on every icon-only or single-tap control (ring tap-to-open-
  breakdown area, stat-tile tap-to-explain area, history swipe-to-delete reveal button, date-
  row tap target, month-header chevron if collapsible). Carried forward from Phase 3, non-
  negotiable per Apple HIG.
- **1px hairline** dividers/borders (`StyleSheet.hairlineWidth` or literal `1`) between history
  day rows, stat tiles, chart card edges, ledger fields — matches `HAIRLINE_WIDTH` token.
- **Readiness dot:** 8px diameter circle — below the 4px base scale, a fixed decorative
  dimension, not a spacing unit.

**Additional semantic (required, beyond the template's 4 rows):**

| Role | Value | Usage |
|------|-------|-------|
| Caution (amber) | `#CDBE4A` | Reserved for: the readiness status light **only when CAUTION/amber**; the "2 SESSIONS · ADJUSTED" chip (D-26) on multi-session history day rows; reused ⚠ warning badges (unchanged, Phase 3) |

| Ash (secondary/muted) | `#8A9098` | Secondary/metadata text; the CTL trend-chart line (D-18); history REST-row label + date; inactive tab icons; chart axis labels; stat-tile mono captions; hairline cursor in the scrub tooltip |

**One-Volt Discipline (D-09) — explicit resolution of a real ambiguity:**
`DESIGN-SYSTEM.md` §5's generic "Session rows" spec says the session HSS number renders "in
volt mono/expanded." That predates D-09's phase-4-specific hard rule that **the ring + its
number are the only volt-filled element above the fold on Home**. To avoid two volt numbers
competing on the same screen:
- **Today's session rows (D-23)** and **stat tiles (D-21)** render their numbers in **bone**
  (Archivo, `tabularNums`), NOT volt — even though they are numeric "hero-ish" values. Only
  the ring's own number is volt.
- **History day rows and the session-detail/breakdown-sheet total row** (separate screen/
  sheet, never visible at the same time as the Home ring) MAY use volt for their total, per
  Phase 3's existing `HSSBreakdownSheet` precedent (`total` style: `Typography.heading` +
  `Colors.dark.accent`). Reuse that exact pattern for the new session-detail screen.
- When the readiness band is PRIMED/green, the status light's dot+label is ALSO volt — this
  is the one **locked, intentional** exception to "one volt element per screen" (D-09
  explicitly permits it: the light's volt is semantic/state-driven, not decorative, and reads
  as "the machine agrees you're green," distinct from the ring's "this is the number").

Accent reserved for: the six elements listed in the table above — nothing else. Specifically
NOT volt: chart lines (D-18, bone/ash only), stat-tile numbers, session-row numbers, ghost
buttons on Home (D-09 — "buttons on home go ghost", i.e. transparent fill + `line` border +
bone text, never volt-filled), the activity-type segmented control's active fill on the run
form (see below), inactive tab icons, REST rows, month-header text.

**Segmented-control convention carried forward (Phase 03 State.md decision):** "Segmented-
control active fill switches volt→bone whenever the same screen/modal already has a volt-
filled primary CTA." The run-entry form's RUN/ERG/CONDITIONING segmented control sits on the
same screen as the volt "Save Run" button — so its active segment fill is **bone** (void
text), never volt. Track is steel, inactive segments are transparent/ash text.

## Component & Interaction Notes

Concrete visual specs for every CONTEXT.md-locked component, resolving all "Claude's
Discretion" items and any genuine gaps CONTEXT.md left open.

### 1. HSS Ring (home 200px + finish mini 84px + calibrating variant)

- **Geometry:** SVG circle (react-native-svg, already a transitive dep of `expo-symbols`/
  victory-native's Skia stack — confirm availability, otherwise add), stroke-based, not fill-
  based. Home ring: 200px diameter, 14px stroke width, round linecap. Mini ring (finish
  screens, both lift AND run per D-04): 84px diameter, 8px stroke width, round linecap.
- **Track:** always steel (`#1F2329`), full circle, drawn first.
- **Progress (non-calibrating states):** volt (`#C6F23D`) stroke-dashoffset arc. **Ring fill
  percentage is capped, independent of the displayed number** (gap CONTEXT.md didn't cover —
  resolved here): `fillFraction = Math.min(hssValue / 200, 1.0)`. Rationale: a single hard
  session ≈ 100 HSS (Phase 2's calibration anchor); a double-session day commonly lands
  120–220. Capping the visual arc at a 200-HSS reference keeps the ring legible (never over-
  wraps) while the **displayed number is always the exact, uncapped rounded HSS** — the ring
  never lies about the number, only about how "full" a circle can look. Use the same 200
  reference and formula for both the home ring (today's day HSS) and the finish mini-ring
  (single session HSS), so there is exactly one constant (`RING_FILL_REFERENCE_HSS = 200`) to
  reason about.
- **Calibrating variant (D-02/D-08):** entire ring renders steel (track color) — no volt arc
  at all, regardless of any interim HSS value. Inside the ring, the animated plate-orbit mark
  (see §2) sits where the readiness light will eventually render below. Mono label under the
  ring reads "BUILDING TREND · DAY {N}/14" instead of "HYBRID STRESS".
- **Number:** home ring uses `Typography.displayXl` (60px, new role above), volt,
  `tabularNums`, centered. Mini ring uses `Typography.heading` (22px/800), volt,
  `tabularNums`, centered. Mono sub-label "HYBRID STRESS" (Mono role, ash) sits beneath the
  number inside both ring sizes (home ring has room for it inside the 200px circle below the
  number; the 84px mini-ring may need the label to sit just below the ring rather than inside
  it, given 84px is too small to fit both a 22px number and a legible mono line — **executor
  discretion on inside-vs-below placement for the mini ring only**, home ring's label MUST be
  inside).
- **Animation policy (D-05):** stroke-dashoffset fill (200ms delay then ~600–800ms
  ease-out, matching DESIGN-SYSTEM.md's "under ~800ms" ceiling) + number count-up
  (Reanimated `withTiming`, same 500ms ease-out-cubic pattern already used in
  `LiveHssHeader.tsx`) runs **once per day**: on the first Home view of the calendar day, or
  whenever today's HSS value changes (a new session finishes while Home is open/returned to).
  Persist a `lastAnimatedHssDate` + `lastAnimatedHssValue` pair (e.g. in a lightweight
  Zustand slice or `AsyncStorage`) so repeat visits within the same day/value render the ring
  instantly at its final state with no animation — this is an implementation detail for the
  planner, but the **visual outcome** (animate-once, static-after) is the locked contract.
- **Tap target (D-24):** the entire ring circle (200px, well above 44px minimum) is a single
  Pressable that opens the today-breakdown sheet — reuse `HSSBreakdownSheet.tsx`'s pattern
  (per-session subtotal rows + a session-total row that also surfaces the D-26 double-session
  math when applicable), adapted to per-session (not per-exercise) rows for Home's mixed
  lift+run day.

### 2. Plate-orbit mark (calibrating state, D-08)

- Nested ellipses (2–3), bone (`#F2F1EC`), tilted −30°, drawn to fit inside the ring's inner
  diameter (home ring: ~140px working area after the 14px stroke + padding; scale
  proportionally for any other size). **No runner glyph** — user-directed deviation from
  DESIGN-SYSTEM.md §4's plate+runner pair; only the plate exists here.
- Animation: continuous slow rotation, ~6s linear infinite (matches DESIGN-SYSTEM.md §4's
  timing spec, applied to the plate alone). Runs only while `readinessBand === 'calibrating'`.
- Lives centered inside the ring, replacing the volt number that would otherwise occupy that
  space — the ring in calibrating mode shows the plate orbit ABOVE the "BUILDING TREND · DAY
  N/14" label, not simultaneously with a numeric HSS value (there's no meaningful readiness
  number to show yet).

### 3. Readiness status light (D-02/D-08)

- Row directly beneath the ring, `Spacing.sm` (8px) gap from the ring's bottom edge.
- Layout: 8px circular dot + `Spacing.xs` (4px) gap + Mono-role label, horizontally centered,
  ~24px row height.
- **PRIMED:** dot + label both volt (`#C6F23D`), dot pulses (opacity 1.0 ↔ 0.5, ~1.2s ease-
  in-out infinite loop — a calm "alive" pulse, not urgent).
- **CAUTION:** dot + label both amber (`#CDBE4A`), same pulse.
- **OVERREACHING:** dot + label both molten (`#FF5A1F`), same pulse (do NOT speed up the
  pulse for red — "calm but honest," not alarmist, per brand voice).
- **Calibrating:** this row is absent entirely (not rendered) — its space is occupied by the
  ring's internal plate-orbit + "BUILDING TREND" label instead (D-08 explicitly: "Lives in
  the calibrating state where the readiness light will eventually appear").
- Readiness never hides once out of calibration (D-06) — even before any session logged
  today, the light shows the CURRENT band derived from history, independent of today's
  (zero) HSS.

### 4. Stat tiles — ATL / CTL / TSB (D-21/D-24)

- Three tiles in a horizontal row, equal width, `Spacing.lg` (16px) gaps, carbon surface,
  hairline border, radius `Radius.md` (8px) — matches the shipped card convention (Phase 3
  uses `Radius.md`/8 for all cards/fields uniformly; ignore `theme.ts`'s aspirational
  sm=6-for-buttons comment, follow the ACTUAL shipped convention).
- Each tile: big number top (Archivo — reuse `Typography.heading`, 22px/800, bone, NOT volt
  per One-Volt Discipline above, `tabularNums`), mono caption beneath (Mono role, ash,
  "ATL · ACUTE" etc.), `Spacing.sm` internal padding.
- **Tap interaction (D-24):** tapping a tile flips it in place (simple opacity/height cross-
  fade, ~200ms — no need for a 3D flip) to show the one-line Label-size explainer copy (see
  Copywriting Contract) in place of the number+caption; tapping again flips back. Tap target
  is the full tile (comfortably above 44px in both dimensions).
- **TSB sign formatting:** always show an explicit sign — "+14" or "−6" (never bare "14").
  This is the one tile whose number can be negative and the sign IS the information (fresher
  vs. more fatigued).

### 5. Trend chart + scrub tooltip (D-18/D-19/D-20/D-22)

- Card container: carbon surface, hairline border, radius `Radius.md` (8px), full screen
  width minus `Spacing.lg` (16px) horizontal margins, ~180–200px chart height.
- Two lines: ATL = bone (`#F2F1EC`), CTL = ash (`#8A9098`). No volt anywhere on the chart
  (D-18). Line weight ~2px, no fill/area beneath (telemetry line style, "no chart junk" per
  DESIGN-SYSTEM.md §5).
- Gridlines: steel, 1px, horizontal only (no vertical gridlines — keep it clean).
- Axis labels: mono, 9px, ash, sparse (e.g. every 7th day for a 28-day window — exact density
  is executor discretion per CONTEXT.md).
- TSB is NOT drawn as a third line — it's represented only by its stat tile (one source of
  truth, D-18) and inside the scrub tooltip.
- **Scrub interaction (D-19):** touch-drag across the chart area shows a vertical hairline
  cursor (1px, ash) that snaps to the nearest day's x-position (gesture mechanics are
  RESEARCH/PLAN territory — victory-native's Skia gesture API should be researched
  specifically per CONTEXT.md's flag). While scrubbing, a small floating tooltip card
  (carbon surface, hairline border, radius `Radius.md`/8, ~`Spacing.sm` padding) appears
  above the touch point (offset upward so the finger never covers it) containing the D-20
  copy: `"{MON DD} · HSS {N} · ATL {N} · CTL {N} · TSB {±N}"` all mono, bone/ash text (no
  volt). Tooltip appears/disappears instantly with the gesture — no fade animation required.
- Rest days (0 HSS) still show ATL/CTL/TSB in the tooltip (D-20 — EWMA always has values,
  even on a zero-input day).
- **Calibrating state (D-22):** the chart renders with whatever days of real data exist (1,
  5, 12…) — never a fake/placeholder line. Caption "BUILDING TREND · DAY {N}/14" (mono, ash)
  sits above or below the chart card (executor discretion on exact position — recommend
  above, matching the ring's internal calibrating label for visual echo).

### 6. Today's session rows (D-23)

- List item: title (Heading role reused at its existing 22px, OR consider a smaller in-list
  size — recommend reusing Body role at 16px/400 for the exercise/activity title here instead
  of full Heading, since these are list rows not screen titles; **Body role, bone, semibold
  feel achieved via Archivo_500Medium if available, else Body role as-is** — this is a minor
  discretion resolution: D-23 says "Archivo semibold," Body role is Archivo 400 — use
  `Archivo_500Medium` explicitly for this one row title only, matching the `label` role's
  font family choice) + mono metadata line beneath (Mono role, ash: `"LOWER · 6 LIFTS · RPE
