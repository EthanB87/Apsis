# Phase 05 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is a **React Native / Expo app** (not React DOM) — the shadcn gate is not
applicable, consistent with Phase 03/04's UI-SPECs. Per `ROADMAP.md`'s UI hint ("no new
screens beyond the permission prompt") and `05-CONTEXT.md`, this phase's UI surface is
**deliberately small**: it is an adapter/import phase, not a new logging surface. No new
design tokens (spacing/typography/color) are introduced — every element below reuses
`apps/mobile/constants/theme.ts` / `constants/Colors.ts` exactly as Phase 03/04 shipped
them. This document exists to remove ambiguity from the five concrete UI touch-points
`05-CONTEXT.md` locks in, not to redesign anything.

**Actual UI surface this phase introduces (nothing more):**
1. One new terminal onboarding screen (`app/onboarding/healthkit.tsx`, D-23).
2. One new Settings section ("Apple Health": connect row / connected+toggle/last-sync, D-03/D-19/D-21/D-24).
3. One new source-provenance chip ("APPLE HEALTH", D-08) on two existing screens (session detail, History session sub-rows).
4. One new soft inline warning on the existing run entry form (D-09).
5. One new transient notice on the existing TODAY screen (D-10).

No new tab, no new navigation stack, no new modal pattern, no new chart, no new logging
form. All 25 CONTEXT.md decisions (D-01..D-25) are treated as locked inputs; this document
resolves the visual gaps CONTEXT.md left to "Claude's Discretion" for the UI-facing subset
of those decisions (D-08, D-09, D-10, D-19, D-20, D-21, D-24).

phase introduces **zero new hex values** — every element below is one of the seven
existing tokens.

| Role | Value | Usage this phase |
|------|-------|-------------------|

**Additional semantic (reused, not new):**

| Role | Value | Usage this phase |
|------|-------|-------------------|
| Caution (amber) | `#CDBE4A` | D-09's soft dedupe hint text (reuses the exact `warningLabel`/`modalWarning` amber convention already shipped for out-of-range values — "an honest heads-up," not an error) |
| Steel | `#1F2329` | Settings toggle track color when OFF; connect-row default background if the executor chooses to give it a subtle steel fill (optional — see Component Notes §2, plain transparent row is also acceptable) |
| Bone (primary text) | `#F2F1EC` | `healthkit.tsx` headline + body text; Settings row labels; Settings toggle thumb color when OFF |
| Void | `#0B0C0E` | Settings toggle thumb color when ON (contrast against the volt track, matching the existing `onAccent` void-on-volt convention used everywhere else in this app) |
| Ash (secondary/muted) | `#8A9098` | Settings sub-copy; "LAST SYNC"/"SYNC PAUSED" mono line; "APPLE HEALTH" chip text + tinted background; "Not now" link text + its sub-copy; TODAY import notice text |

**One-Volt Discipline compliance:** `healthkit.tsx` has exactly one volt element (the
primary button) — the "Not now" link is plain ash text, never a second button style. The
Settings screen's existing volt-filled "Save changes" button (inside `ProfileReview`)
remains the screen's single primary CTA; the new toggle's volt-when-ON state is a
**state indicator**, not a competing CTA fill — this is the same "semantic, not
decorative" exception `04-UI-SPEC.md` already carved out for the readiness light's
PRIMED/volt state, applied here to a binary on/off control instead of a tri-state light.

Accent reserved for: the two elements listed above — nothing else this phase adds. The
"APPLE HEALTH" chip is explicitly **ash-tinted, not volt** (per D-08's own wording,
"fits the ledger language: mono captions, ash tint") — this is a provenance label, not an
accent element.

## Component & Interaction Notes

### 1. Onboarding HealthKit step (`app/onboarding/healthkit.tsx`, D-23/D-20/D-22)

**Not a `WizardStep` reuse — a deliberately quieter, standalone terminal screen.**
Resolved gap: `WizardStep.tsx` has no secondary-action slot and its progress-dot chrome
assumes the wizard is still in progress. This step runs *after* `review.tsx`'s Save has
already inserted the `user_profile` row — the wizard is functionally complete. Reusing
`WizardStep` (with its "Step N of 6" progress dots) would falsely imply more setup is
required. Build a standalone screen with matching chrome instead:

- `SafeAreaView` (void background, `edges={['top','bottom']}`), same as every onboarding
  step.
- **No progress dots** (the profile is already saved — this is a bonus step, not part of
  the counted sequence).
- Top padding `Spacing.xxxl` (48px) above the headline — quieter than `WizardStep`'s 64px
  top padding, signaling "you're basically done."
- Headline: `Typography.heading` (22px/800, uppercase, bone), left-aligned, matching
  every `WizardStep` question's exact style, `Spacing.xl` (24px) below it before body copy.
- Body copy: `Typography.body` (16px/400, bone), `Spacing.xxl` (32px) below it before the
  pinned action block.
- **Optional (executor discretion, not blocking):** a short 2-3 line mono benefit list
  below the body copy, styled like `DESIGN-SYSTEM.md` §6's onboarding-paywall benefit
  rows but simpler (no icons required) — e.g. "IMPORT RUNS · HR · BODYWEIGHT" / "WRITE
  YOUR SESSIONS BACK" / "NO DUPLICATES, EVER" (`Mono` role, ash). Cut this under time
  pressure without violating any locked decision.
- **Pinned action block** at the bottom (mirrors `WizardStep`'s button positioning:
  `marginHorizontal: Spacing.lg`, `marginBottom: Spacing.lg`):
  1. Primary button "Connect Apple Health" — identical chrome to `WizardStep`'s button
     (`minHeight: 48`, `Radius.md`, volt fill, void text, `accentPressed` on press).
     `onPress` calls `requestAuthorization` (Pattern 4, `05-RESEARCH.md`) then advances
     (background 90-day import per D-22 — screen does not wait/block on it).
  2. `Spacing.sm` (8px) gap, then the "Not now" link: `Typography.label` (13px), ash
     text, centered, `minHeight: HIT_TARGET_MIN` (44px) tap target, no border/fill
     (plain text button).
  3. Immediately below the "Not now" link (always visible, not a toast — **resolved
     interpretation of D-20's "quiet line"**): static `Typography.label` (13px), ash,
     centered, text: "You can connect anytime in Settings." This is visible *before* the
     user taps "Not now" as much as after — it sets the expectation, then tapping "Not
     now" simply advances immediately with no additional dialog/toast.
- Both the primary button and the "Not now" link advance past this screen (to the tab
  shell) — declining is never a dead end and never re-prompts (D-20, "no re-prompts, no
  nagging" — this screen must never be shown again once passed, regardless of the
  button pressed).

### 2. Settings "Apple Health" section (`app/(tabs)/settings/index.tsx`, D-03/D-19/D-21/D-24)

New section inserted after "Default Rest Timer" and before the "Apsis vX.X.X" footer,
using the existing `sectionLabel` style ("Apple Health", same uppercase/ash/`Spacing.xxl`
top padding convention as "Profile"/"Units"/"Default Rest Timer" above it).

**State A — not connected:**
- Single tappable row, reusing `ProfileReview`'s row visual pattern exactly: `minHeight:
  HIT_TARGET_MIN + 12`, `paddingVertical: Spacing.lg`, hairline bottom border, pressed
  opacity 0.7, `Spacing.xs` gap between label and sub-copy.
- Label: "Connect Apple Health" (`Typography.body`, bone).
- Sub-copy directly beneath: "Import runs and bodyweight. Your logged sessions go to
  Health too." (`Typography.label`, ash).
- Tapping the row calls `requestAuthorization` — same call as the onboarding step's
  button, this is the permanent re-entry point for users who declined onboarding or are
  on an existing install (D-03).

**State B — connected:**
- The same row now renders as a non-tappable info row (no `pressed` opacity, no
  `accessibilityRole="button"` on this line): label "Connected" (`Typography.body`,
  bone), sub-copy "Manage permissions in the Health app." (`Typography.label`, ash).
- **New toggle row directly beneath it** (`Spacing.md`/12px gap from the row above):
  flex-row, `justifyContent: 'space-between'`, `alignItems: 'center'`, `minHeight:
  HIT_TARGET_MIN` (the full row is the tap target, not just the `Switch`):
  - Left: label "Sync with Apple Health" (`Typography.body`, bone).
  - Right: a native RN `Switch` — `trackColor={{ false: Colors.dark.steel, true:
    Colors.dark.accent }}`, `thumbColor={value ? Colors.dark.background :
    Colors.dark.text}` (void thumb on volt track when ON, bone thumb on steel track
    when OFF — matches the existing void-on-volt / bone-on-steel conventions used
    everywhere else in this app, e.g. `ChoiceButton`'s selected state).
  - Toggling OFF pauses all HK reads/writes (D-21) — already-imported sessions are
    **not** removed or visually marked differently; this is a pure sync-pause, not an
    unlink.
- **Sync-status mono line** directly beneath the toggle row (`Spacing.sm`/8px gap,
  `Mono` role, ash, `fontSize: 13` per the existing `footerText` convention):
  - Toggle ON: "LAST SYNC {H:MM AM/PM}" (or "LAST SYNC —" if no successful sync has
    completed yet).
  - Toggle OFF: "SYNC PAUSED" — replaces the timestamp line entirely so a frozen,
    increasingly-stale "LAST SYNC" time is never shown while paused (resolved gap;
    CONTEXT.md's D-24 only specified the ON-state copy).

### 3. Source badge — "APPLE HEALTH" chip (D-08)

Reuses `DayRow.tsx`'s existing pill-chip pattern (`Radius.pill`, `Mono` role at
`fontSize: 11`) with an **ash tint instead of amber** (a new color variant of an
already-shipped shape, not a new component):
```
backgroundColor: 'rgba(138,144,152,0.15)'  // ash at 15% opacity, same formula as the existing amber chip
color: Colors.dark.mutedText               // ash, full opacity text
```
Renders only when the underlying `workout.source === 'healthkit'` — absent for manually
logged sessions (no chip is not an error state, it's the default/expected case for the
vast majority of sessions).

**Placement — two sites, both retrofits of existing components:**
- **Session detail** (`app/session/detail.tsx`): chip renders inline to the right of the
  existing `timestamp` line (flex-row, `Spacing.sm`/8px gap), before the `title` line.
  Does not affect the existing per-exercise/segment rows or the total row below it.
- **History session sub-rows** (`components/history/DayRow.tsx`, inside the accordion's
  `sessionRow`): chip renders inline to the right of `sessionLabel` (flex-row,
  `Spacing.xs`/4px gap), matching exactly how the day-level "N SESSIONS · ADJUSTED" chip
  already sits inline next to `dateLabel` one level up in the same component. The
  `DaySession` interface gains a `source: 'manual' | 'healthkit'` field to drive this
  (schema/data-layer concern for the planner, not a new visual decision).

### 4. Soft dedupe hint — run entry form (D-09)

Reuses the exact `warningLabel` pattern already shipped in `app/(tabs)/log/run.tsx` for
the HR/pace out-of-range warnings (`Typography.label`, `Colors.dark.warning`/amber,
non-blocking, appears directly beneath the relevant field).

- Placement: directly beneath the **Date row** (§7 step 6 in `04-UI-SPEC.md`'s numbering)
  — this hint is date-driven (D-06's dedupe rule keys off `localDate`), so it belongs
  next to the field the user is most likely to be adjusting when the collision becomes
  relevant.
- Trigger: whenever the currently-selected date already has an imported (`source ===
  'healthkit'`) session whose duration is within the same ~±15% tolerance the import
  pipeline itself uses (D-06's constant, reused — not a second tolerance value).
- Copy: "An imported run already covers this — saving will count both." (exact string,
  Copywriting Contract above).
- Never blocks Save (clamp-and-warn continuity, Phase 3 D-03) — the "Save Run" button's
  enabled/disabled state is unaffected by this hint's presence.

### 5. TODAY transient import notice (D-10)

Placement: directly beneath the "LET'S WORK" greeting line, above the `HssRing` block —
this is deliberately the top of the scroll, since the notice exists to explain *why the
ring is about to visibly move* (D-10's own rationale), so it must be seen before the
ring, not after it.

- Style: single-line `Mono` role, ash, centered, `Spacing.sm` (8px) top margin from the
  greeting line above it. No card/background — a quiet inline line, not a banner/toast
  component (matches the brand voice: "quiet transient mono notice," not an alert).
- Copy: "IMPORTED {N} SESSION{S} FROM APPLE HEALTH" (singular/plural per the Copywriting
  Contract above). Silent (renders nothing, takes no layout space) when a foreground
  sync completes with zero new imports — this is the default/common case on every sync
  after the first.
- **Presentation lifecycle (Claude's Discretion per CONTEXT.md, resolved minimally):**
  the notice is tied to a specific completed import batch, not a persistent flag. It
  disappears the next time the TODAY screen is freshly focused *after* having been shown
  once for that batch (i.e., leave the tab and come back, or background/foreground the
  app) — no explicit dismiss tap is required, and it never reappears for the same
  batch. This keeps the implementation to a simple in-memory "last shown batch id"
  check (mirrors `index.tsx`'s existing `lastAnimatedHssDate`/`lastAnimatedHssValue`
  module-scoped pattern for the ring's animate-once gate) rather than a new persisted
  dismissal table.
